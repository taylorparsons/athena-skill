# ATHENA v2.1.0 — Token Diet

**Release date:** 2026-07-05
**Repo:** taylorparsons/athena-skill
**Full change list:** CHANGELOG.md (v2.1.0)

ATHENA v2.1.0 cuts fixed per-session token overhead by ~94% and keeps the full audit trail. The knowledge base is unchanged in scope — requests, decisions, specs, tasks, commits — but agents stop reading it wholesale. A deterministic script, `./scripts/owl`, now mediates every log access. Sessions pay for answers, not archives.

## Measured impact

I measured these numbers in the athena-skill repository itself (30 features, 5 months of history). Token counts are approximated as characters ÷ 4.

| Surface | When it loads | Before | After | Reduction |
|---|---|---:|---:|---:|
| Session-open doc reads (requests.md, decisions.md, PRD.md; plus athena-index.md and progress.txt without memory) | Every session | ~22,600–28,600 | ~220 (`owl context`) | **~99%** |
| SKILL.md loop instructions | Every task | ~3,935 | ~1,281 | **67%** |
| Skill frontmatter description | Every session, every project | ~148 | ~59 | **60%** |
| Codex AGENTS.md | Every Codex session | ~860 | ~145 | **83%** |
| **Fixed overhead per session** | | **~26,700–32,600** | **~1,450–1,660** | **~94%** |

A typical working session also loads the active feature's spec and tasks (~1,000–2,000 tokens). Total: ~4,000 tokens where v2.0 spent ~30,000. The savings compound with project age — the old layout re-read append-only logs that only grow; the new layout's cost is flat.

## What changed

- `owl context` replaces reading five docs files at session open: one command prints the active feature, goal, task state, recent CR/D IDs, and the latest request. Identical on Claude Code and Codex — no hooks required.
- `owl add-request`, `owl add-decision`, and `owl add-note` append audit entries with generated, collision-safe IDs. Writing to the trail no longer requires reading it.
- `owl show <ID>` retrieves one entry; `owl why <FR-ID>` walks a requirement to its sources, tasks, and commits. Query cost scales with the answer, not the log size.
- `docs/progress.txt` is retired. Task state lives in each feature's `tasks.md`, session notes in each feature's `notes.md`. Archiving a feature removes its history from every future session at zero cost.
- SKILL.md dropped from 338 to 86 lines. Setup, commit ceremony, and recovery procedures moved to `references/`, loaded only when a session needs them.
- Codex `AGENTS.md` guidance dropped from 76 to 8 lines: trigger plus stop-gates. The loop is defined once, in SKILL.md.

## Upgrading

1. Pull v2.1.0 and reinstall the packaged skill (`skills/athena/`) into `~/.claude/skills/athena` and `$CODEX_HOME/skills/athena`.
2. Run `./scripts/owl migrate` once per repo. It moves each progress.txt session block into the matching feature's `notes.md`, parks unattributable blocks in `docs/audit/progress-legacy.txt`, and deletes `progress.txt`. The command is idempotent and lossless.
3. Unmigrated repos keep working: every owl command falls back to `progress.txt` until you migrate.
